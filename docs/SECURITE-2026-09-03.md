# AKORA — Relevé de sécurité du 03/09/2026

Tout ce qui suit a été **mesuré** (API de gestion Supabase en lecture, `scripts/verifier-securite.mjs`,
`npm audit`, en-têtes HTTP relevés par `curl -I`, console du navigateur en production), puis
**corrigé** quand c'était possible depuis ce poste. Chaque ligne dit ce qui a été vu, ce qui a
été fait, et ce qui reste.

## Ce qui a été corrigé le 03/09

| Constat | Fait |
|---|---|
| `anon` détenait INSERT / UPDATE / DELETE / **TRUNCATE** / REFERENCES / TRIGGER sur 23 tables et vues — droits par défaut de Supabase, RLS n'ouvrant aucune écriture à anon | révoqués ; privilèges par défaut du rôle `postgres` alignés pour les tables à venir (`20260903150000_durcissement_droits.sql`) |
| `authenticated` détenait TRUNCATE / REFERENCES / TRIGGER sur 47 tables | révoqués |
| 8 RPC exigeant un compte étaient exécutables par `anon` (elles levaient) | plus exécutables du tout |
| Aucune en-tête **Content-Security-Policy**, aucune **HSTS** | ajoutées dans `public/.htaccess` ; CSP calculée sur les origines que le code appelle ; vérifiée en production : 0 blocage sur 4 pages |
| react-router 6.30 : redirection ouverte par antislash (CVE-2025-68470 et contournement), correctif en v7 (rupture) | `retourInterne` refuse tout antislash, toute double barre, tout schéma déguisé, toute remontée de dossier — 5 tests |
| TLS non imposé sur les connexions directes à la base | imposé (`ssl-enforcement`) |
| Changement de mot de passe sans reconfirmation d'identité | reconfirmation exigée |

## Ce qui reste, et pourquoi

| Point | Pourquoi ce n'est pas fait | Quoi faire |
|---|---|---|
| Contrôle des mots de passe compromis (HIBP) | réservé au plan Pro (refus 402 de l'API) | activer avec le passage au plan Pro |
| Captcha à l'inscription | demande une clé Turnstile ou hCaptcha | créer la clé, puis `security_captcha_enabled` |
| react-router v7 | changement majeur (routes, types) — pas en même temps que le chantier mobile | une branche dédiée, avec la suite de tests |
| Restriction des adresses IP de la base | l'adresse d'Andry change ; les scripts passent déjà par l'API de gestion | à faire si un accès direct devient nécessaire |
| `uri_allow_list` contient `http://localhost:8080/**` | utile au développement local OAuth | retirer si plus personne ne développe en local |
| Exigence de caractères dans les mots de passe (côté GoTrue) | le site note déjà la force (`mot-de-passe.ts`) ; imposer côté serveur casserait les comptes existants à la connexion ? non, seulement à la création | décider : lettres + chiffres, 8 minimum |
